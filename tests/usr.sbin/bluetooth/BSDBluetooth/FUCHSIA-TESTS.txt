The BSD-2-Clause license reproduced below applies to this adaptation too.
An actual SOCK_SEQPACKET peer replaces Fuchsia's socket/FIDL test transport;
a bounded native monotonic deadline replaces its fake executor timer. The
stale response's wire contents and transaction-label separation are retained.
A second, distinguishable response proves completion belongs to the new call.
This is an adapted test, not execution of the upstream Rust suite.

audio_avdtp_test:fuchsia_acceptor_start_suspend_abort uses the state-transition
oracle from stream_endpoint.rs::start_and_suspend at the same pinned revision:
https://fuchsia.googlesource.com/fuchsia/+/9b7f2acde09d777a85d6c2172fb8343f77bdfd7a/src/connectivity/bluetooth/lib/bt-avdtp/src/stream_endpoint.rs
Copyright 2018 The Fuchsia Authors. All rights reserved.
The native test adds Abort/reconfigure coverage. Native discovery, restart,
media backpressure and fuzz tests are new 5BSD tests inspired by the test
families; they are not copied Fuchsia test implementations.

fuchsia_gatt_test contains 44 adapted ClientTest cases from Fuchsia's GATT

Adaptation boundary
The adapted upstream test names, request/response octets and successful
discovery results are retained. A socketpair peer validates each outgoing request
before delivering the corresponding response. The native synchronous GATT
call replaces Fuchsia's Client callbacks and mock L2CAP channel. Tests use
production ATT/GATT logic; controller/logging hooks come from test_common.h.
This is software protocol testing, not radio or kernel L2CAP interoperability.

Fuchsia HostError::kPacketMalformed maps to a negative native result; ATT
error codes retain their wire values. Native read-error tests require outlen=0
as the equivalent of Fuchsia's empty callback value. Malformed fixed-size
responses check the failed bearer and prohibit another write on that bearer.
Fuchsia-specific callback delivery, Inspect state and object lifetime are
outside this adapter. It does not assert physical link teardown.

ExecutePrepareWritesErrorFailure uses the native long-write convenience API:
the upstream first prepare/error/cancel wire sequence is retained, but the
never-transmitted second queued fragment is not represented by our API.
ExecuteWriteMalformedResponse extends WriteRequestMalformedResponse to the
Execute opcode. PrepareWriteValueEchoCorruptionSweep extends the reliable
write corruption cases across three value octets and short/long echoes.
These two names are native extensions, not original upstream test names.

Additional native comparisons inspired by Fuchsia
smp_keys_edge_test checks stable local identity versus private on-air addresses,
using Phase3::SendIdentityInfo and InitiatorSendsLocalIdKey as references.
l2cap_data_deep_test checks maximum-frame overflow and recovery, inspired by
RecombinationDroppedForFrameWithMaxSize. It runs the kernel receive routine
with userspace mbuf fixtures, not a running kernel or radio.
Exact per-case references are in spec_test_references.tsv.

One deliberate comparison difference
DiscoverPrimaryEmptyDataList retains Fuchsia's expected success as a scoped
ATF expected failure. Fuchsia explicitly tolerates this malformed reply.
5BSD rejects it with EPROTO. Core 6.2 Vol 3 Part F Table 3.25 specifies a
minimum four-octet Attribute Data List, so no production parser was relaxed.
The test independently requires the exact native rejection. Packet exchange,
completion count and output count checks are outside the expected failure.
Kyua may count expected failures as successful outcomes in its summary; do
not describe this case as matching Fuchsia.

The native removed-cache case removes an adapter rather than a Fuchsia peer.
Three-second cache expiry and suppression of replay to existing clients are
5BSD policy checks, not assertions that Fuchsia uses the same cache lifetime.

audio_avdtp_test:fuchsia_acceptor_get_configuration adapts get_configuration
in bt-avdtp/src/stream_endpoint.rs at the existing audio reference revision
9b7f2acde09d777a85d6c2172fb8343f77bdfd7a. It verifies configuration is absent
before setup and after abort, and exact negotiated SBC fields in between.

Current Sapphire/Pigweed discovery and peer-cache tests were also reviewed at
83c98d69b2d8f251c46c59e6b1c6231355a30474. Those files are Apache-2.0, not BSD.
No code from those Apache-licensed files is imported by this review; the
adapted expectations above use the identified BSD-licensed Fuchsia sources.

Expanding coverage
Add independently attributed upstream cases at the corresponding 5BSD API
boundary: characteristic/descriptor discovery and ATT read/write first,
then SMP pairing transcripts, L2CAP segmentation/signaling and HCI command
queues. Each needs explicit result/error mapping and documented differences.
Keep upstream expectations separate from 5BSD-specific assertions. Preserve
the revision and license when copying further fixtures.

Running upstream itself
Current Sapphire lives in Pigweed and documents:
bazelisk test --config googletest //pw_bluetooth_sapphire/host/...
https://pigweed.dev/pw_bluetooth_sapphire/#running-tests
That target exercises Sapphire. It does not substitute 5BSD's implementation.
The original upstream runner has not been built or executed by this adapter.
