# ARM64/RISC-V USB serial/input module qualification

## Qualified scope (2026-11-03)

Twenty-nine module leaves per architecture pass four normal build-bsd native
profiles and 116 independent original Make controls. All 58 plain modules match
original Make whole-file bytes. The 58 CTF/runtime comparisons preserve every
ELF section and section-layout contract except explicit build-ID/debuglink
values; note metadata/encoding and both native/original debuglink CRCs pass.
Standalone debug files differ in 58 comparisons; semantic DWARF and actual
debugger source lookup remain open.

All 116 actual module compilation contexts preserve original compiler policy
and 15,232 canonical consumed source/generated-input pairs. All 232 actual
ordered link stages preserve flags and object order. All 174 installation
records match destinations, ownership, modes and package/debug tags. Original
staged payloads equal their Make products, and each native installation source
binds its captured producer output.

Before/after checks preserve 8,577 original
source/header/schema/tool/Make-policy inputs. The explicit
disabled-configuration sentinel /dev/null is recorded separately from 64
regular Makefiles. Source-owned declarations, actual native compiler .d inputs,
generated-input bytes and actual link parameter files are retained and
hash-bound. No target module executes on the host.

## Source-owned integration

Selection intersects the retained parent-export-aware ARM64/RISC-V module
inventories with physical USB serial/ and input/ source families. Each native
module retains its source-owned source/object order, exports, package and
aliases. These resulting declarations are ordinary native Bazel build metadata;
runtime builds do not query Make for source discovery or import Make-generated
objects or headers.

The existing CK header provider already contains the exact required
architecture-adjusted closure and grants the USB package visibility; no
duplicate provider is introduced. Existing target-derived usb/kbd/evdev option
views are reused. New gdb/ukbd views extract members from the actual target
GENERIC configuration tree. Neither option values nor empty fallbacks are
fabricated.

Four actual native-host provider tests inspect all selected target artifacts.
Each requires u3g, uftdi and uvisor to resolve ucom_attach through ucom and
rejects localized known-provider defects. External kernel/USB-core providers
and actual loading are explicitly outside this test's scope. The existing
checker and host-artifact test contract are reused without an additional test
framework.

## Original Make context and current references

The source-list audit retains 58 leaf queries with actual parent-exported
values, GENERIC KERN_OPTS, source Make include paths and private object
directories. Each queried primary source/object list matches the declared
module order. Original controls reuse those contexts and compile with sixteen
jobs, original target ABI flags, private NO_ROOT staging and real installation
METALOG records. No host installation occurs.

Fresh independently generated GENERIC Makefiles and all 359 option headers
match retained references; selected product order and link/post-link policy
also match. The current kernel inventories contain 2,035 ARM64 and 1,194 RISC-V
link products. Their unresolved bindings and missing generated outputs remain
explicit. The physical-source audit checks 2,007/1,185 records and records
five/four changed files since the older inventory. These configuration
inventories do not establish a compiled cross kernel.

KOBJ generated inputs differ from Make only in an exactly checked
schema-provenance comment line, recording an absolute source path versus
basename. Raw hashes and complete byte comparisons remain retained; generated
code and other content are not normalized away. The dependency observer was
extended for the actual usb_if.h producer after correctly rejecting its
initially unrecognized view.

## Observability and runtime follow-up

The bounded scan of all 29 physical C sources finds zero SDT/DTrace/CTR/audit
marker lines and no matching explicit compiled probe sections in the inspected
module outputs. Exact plain/CTF comparisons preserve the original observed
artifacts. This does not establish absent or complete framework/FBT coverage,
live probe delivery or audit event delivery.

Keep runtime follow-ups for USB serial open/read/write/ioctl, tty ownership and
modem controls, transfer cancellation/flush, keyboard/mouse/touchpad
permissions and event delivery, suspend/resume, hotplug and detach/lifetime
handling. No devices, target modules or probes are exercised by these
inspections, and no probe/audit source is changed.

## Maintained workflow and remaining gates

The compiler/input audit is bounded to selected module contexts, Make-policy
bindings and consumed generated bytes. Full helper/bootstrap hermeticity and an
independent toolchain rebuild remain unqualified.

Existing build-bsd/backend format-5 architecture/kernel/CTF/debug/test inputs
and shared module/install rules carry this cohort through the normal frontend.
No frontend C/CLI, SDK/helper, signing, staging-security, publication or
runtime policy change is required. The manual and roadmap record coverage and
qualification limits. Completed receipts bind their original validated
native-r3 SDK/tool state; changed receipt-bound tools require fresh snapshots
rather than rewriting old receipt hashes.

Remaining cross kernels/modules, alternate configurations/options, full
world/rescue/pkgbase, original aggregate installation, bootstrap/base Bazel
packaging, hardware/verified combined publication, semantic DWARF/source
lookup, VM/device/runtime and controlled
CPU/memory/disk-I/O/disk-allocation/cache/sandbox qualification remain
required. Resource counters and disk reserves are safety evidence, not
performance comparisons. Make remains production/default; BIP remains excluded.
No host installation, upgrade, module load or reboot occurs.

## Retained rejected observer attempts

The first source-freshness observer checked the wrong origin discriminator. Its
accepted r2 replacement explicitly counts physical source records and reports
actual changes; option/order checks were unaffected. The first Make control
attempt rejected /dev/null because it is a character-device configuration
sentinel, not a regular policy file. The r2 context classifies it explicitly
and retains 64 regular Makefile bindings; the accepted 116 controls pass. The
first artifact observer rejected the unrecognized usb_if.h view; its
replacement verifies the declared producer and exact checked provenance-comment
difference. All failed logs and earlier data remain available; none of these
attempts is counted as a pass.
