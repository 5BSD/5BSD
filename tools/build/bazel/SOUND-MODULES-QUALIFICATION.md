# Sound module qualification

## Scope (2026-11-02)

The ten remaining local-BUILD gaps in the reviewed amd64 GENERIC sound subtree
now have native Bazel module declarations: sound, snd_driver, snd_dummy, snd_envy24,
snd_envy24ht, snd_hda, snd_hdsp, snd_hdspe, snd_spicds and snd_uaudio. Their 40
objects comprise 33 physical C sources and seven KOBJ-generated sources, compiled
in 35 native groups. Twenty-nine exact physical header contexts reuse 24 existing
providers. Original exports, including sound and snd_spicds public providers,
are preserved. No runtime source, original Makefile or common build helper changes.

## Native source generation and configuration

Existing source-owned KOBJ producers generate hdac, ac97, channel, feeder, mixer,
mpu and mpufoi interfaces. Existing native AWK producers generate feeder_eq_gen.h,
feeder_rate_gen.h and snd_fxdiv_gen.h from their maintained scripts. Consumed
option headers come from the selected native config tree; USB IDs use the existing
USB producer. All consumed default outputs match original Make digests, except
the exactly checked single KOBJ source-path provenance comment. No generated file
is imported from the Make references or committed as a substitute for its rule.

The existing feeder_eq_presets and feeder_rate_presets string settings remain
normal build-bsd build-settings. Their generator default/override/restoration/repeat
qualification is documented in DEVICE-IO-KERNEL-QUALIFICATION.md; this module batch
binds default generated bytes through actual compiler input digests. It does not
claim module qualification for every preset, alternate KERNCONF or architecture.

## Rejected declaration and correction

The first CTF/debug attempt stopped before compilation: migration declarations
missed existing computed-name channel/feeder/mixer header targets and introduced
three duplicate names. The corrected declarations reuse those existing views,
with narrow sound-family consumer visibility. Their generators/outputs and the
previous virtio consumer remain unchanged. The original analysis failure,
rejected source text and correction hashes are retained. Tests or policy were
not relaxed to accept the duplicate graph.

## Maintained workflow and remaining qualification

The existing build-bsd C interface and maintained format-5 backend already carry
selected SDK/kernel configuration, typed CTF/debug settings, target/test inventory
and all sixteen jobs. Source declarations, review evidence and docs are updated
in this change; no new CLI/schema, signing/staging/publication policy or one-off
frontend is needed. Make input discovery is migration review only, not part of
the native production graph.

The source scan retains twelve existing PCM provider/probe declarations/calls for
drain, xrun, trigger and buffer waits. Runtime PCM playback/capture, channel and
mixer controls, MIDI, USB/HDA/HDSP hardware, dummy-driver behavior, concurrency,
latency/underruns, hotplug and error cleanup remain open. So do live DTrace/audit,
load/unload behavior and strict/default loader compatibility; see
MODULE-LOADER-EXPORT-CONTRACT.md. Other existing sound declarations are not newly
qualified by the count of ten closed local-BUILD gaps.

Complete world/cross-architecture/module/package/bootstrap/publication, VM and
CPU/memory/disk I/O/disk-use/cache/sandbox performance gates remain open. Make
stays production/default; BIP is excluded. No host audio module loading, system
installation, upgrade or reboot occurred.
