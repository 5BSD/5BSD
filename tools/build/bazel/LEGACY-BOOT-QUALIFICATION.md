# Native legacy boot and BTX qualification

## Selected world gap and production scope

The fresh maintained world recursion discovers 2,128 selected directories,
including 52 stand directories. Before this cohort stand had no native BUILD
files. Directory inventory is discovery rather than action/install coverage.
This first cohort implements seven real products from that missing world graph:
boot0, boot0sio, mbr, pmbr, cdboot, BTX and its loader. The first five install
under /boot; the two internal BTX products remain uninstalled as original Make
requires. Remaining BIOS/EFI/kboot loaders, their libraries, full rescue/world,
bootstrap and final package/publication closure remain open.

These are selected amd64-world recipes producing i386 ELF32 assembly objects
and flat BIOS/BTX images. Ordinary source-owned cc_library compilation, declared
own-object selection and native cc_binary linking preserve the actual original
compiler-driver chain. The original linker script and consumed bootargs header
have narrow source owners. The serial console variant uses the original shared
boot0.S with its independent flags. Original C, assembly and Make sources are
unchanged; no compiler/runtime/header or producer output is copied from Make.

Source-owned features disable ordinary debug/stack/ELF-security/optimization
injection, then preserve original flags explicitly, including both original
-O2/-Oz positions, nostdinc, freestanding/32-bit/ISA flags, assembly definitions,
warning order, origin/entry/script, flat output, no build ID and original link
hardening arguments. Global/default toolchain behavior is unchanged. Exactly
one original object-directory libsa32 include search root is omitted: no input
or availability query in these six physical assembly sources consumes it.
Other source search paths are relocated to the declared source namespace.
No placeholder headers or broad root-package exports are introduced.

The installed flat images use file installation directly, with no ELF debug
split invented for them. cdboot's original compressed manual is included. The
normal format-5 build-bsd frontend and existing installation archive rules carry
these targets without a C/backend API or shared helper/toolchain extension.

## Independent original proof

Seven fresh maintained install-reference builds run sequentially at 16 jobs
under the object-root disk guard. Before/after hashes bind all 699 original
stand files, including external shared assembly/header/linker sources omitted
from a leaf-only snapshot. Original configuration closures, actual recipes,
objects, flat images, component METALOG and private stages remain retained.

All seven native ELF32 objects are whole-byte identical to their originals,
not only text/allocated subsets. All seven final flat images are also whole-byte
identical. Actual compiler bytes match the original selected staged compiler;
all seven compiler vectors preserve original ordered source policy after
explicit SDK/path/output/dependency plumbing binding. Ten original and native
source/header consumption occurrences match their declared action digests.

All seven actual single-object link vectors preserve original flag/token order,
including the exact whitespace-containing COMSPEED expression. Their compiler,
linker and linker-script digests are bound. The exact current compiler output
feeds its declared byte-preserving object alias and then its accepted link input;
full source/output identity and digest checks distinguish the repeated boot0
basename. nostdlib excludes implicit runtime/library linkage; there is no 32-bit
host-library fallback or target image execution.

The first profile failed at the two boot0 links because its response file lost
COMSPEED argument grouping. Successful assembly and five successful link actions
from that rejected overall profile remain immutable witnesses. Only the two
source-owned link-option quoting strings changed, preserving the entire original
argument through both Bourne-token and compiler-response parsing. The second
profile passes with two fresh links; seven cached compiler outputs and five
cached images are explicitly rebound to successful prior actions by their exact
current input/output digests. The rejected overall profile is not qualified,
and no cached output is claimed as new execution.

## Installation and tests

All six original installation records match exact payload bytes, paths, root/
wheel ownership, 0444 modes and package=bootloader tags: five boot images and
one compressed manual. The two internal products have no installation records.
The archive is a staging artifact, not a final package or host installation.

One maintained host Python test target passes seven unittest methods against
actual declared images/objects: ELF32/i386 relocatable input ABI, four 512-byte
BIOS signatures/empty partition templates, BTX header/text extent, distinct
serial variant and flat loader artifacts. Corrupted signature/header and wrong
ELF class controls are rejected. All images are treated as data. No image is
executed, disk is written, partition is changed or machine is booted.

The bounded seven-context/six-source call-shaped trace/audit scan finds zero
recognized calls. Complete raw original/native bytes preserve existing code.
No live probe/event, security or performance claim follows from this scan.

## Limits and normal frontend

Make remains the production/default world builder. Other boot configuration
values, architectures, loaders and full stand aggregation remain unqualified.
The preserved external SDK and bootstrap dependencies remain explicit. Flat
legacy image equality establishes neither bootability/hardware behavior nor
UEFI signing, bundle signing, verified boot or protection from compromised root.
Existing maintained signing/publication policies are unchanged. No host install,
upgrade, reboot, package construction or publication occurred.

The manual records the existing normal target/test workflow. Its lint
comparison is retained separately; preexisting diagnostics are not called clean.
