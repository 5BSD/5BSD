# Native ninety-one-application rescue construction

## Source-owned policies and generators (2026-11-05)

Init, ping, dhclient, iscsictl, iscsid and tar bring the selected AMD64 core to
91 of 103 default applications. Ordinary/rescue variants share exact source
expressions. Init excludes the ordinary reroot seed under RESCUE. DHCP preserves
its anchored provider and excludes ordinary Casper; ping excludes ordinary Casper.
Tar excludes its ordinary executable provider under the original RESCUE condition;
its native library instrumentation remains intact. iSCSI reuses declared yacc/lex
rules, native tool targets, parser/header/report and lexer outputs.

The rescue macro now represents original NO_W* policies through explicit
omitted_warnings: DHCP omits -Wcast-align, iscsictl omits
-Wmissing-variable-declarations. Unknown or duplicate omissions fail analysis;
other callers keep their existing profiles. Native crypt/libarchive/iscsiutil
archives join the selected original lazy-link order. Target OpenSSL selection
now follows libarchive, preserving Fetch's dependency on that archive.

Ping compiler sources and crunchgen object descriptors select declared IPv4/
IPv6 combinations; its ping6 alias follows IPv6. Only the default dual-stack
configuration is qualified here. Single-family, neither-family and other complete
rescue option combinations remain explicit qualification gates.

## Retained generated-source differences

`bazel-rescue-91-dependency-strict-r1-20261105` rejects literal dependency-byte
parity at iscsictl parse.c. `bazel-rescue-91-generator-controls-r1-20261105` binds
original yacc/lex/m4 and source inputs, then replays both original and native
source/output spellings and explicit output options. Each complete replay output
matches its own retained artifact byte-for-byte. y.tab.h and the verbose parser
report are identical; parse.c and token.c remain byte-different. No byte
normalization is performed. Producer replays qualify those path/naming differences,
not arbitrary generated-input substitutions or live parser behavior.

`bazel-rescue-91-dependency-review-r2-20261105` explicitly reports
**passed-with-differences**. All 3031 consumed occurrences are present in executed
declared-input digest inventories. Independent original name/byte/multiplicity
comparisons agree except exactly those two hash-bound generated C occurrences,
which require the full producer controls. Raw differences are retained individually.
Parent-directory spellings still require bounded relative checks and source
identity; mutable execroot links are not retained-content evidence. Complete
logical namespace and incremental invalidation acceptance remain open.

The original yacc replay also emits its existing warning that PCP is undefined.
The lexer and grammar reference PCP; native and original generator outputs still
match their respective controlled replays. This warning needs diagnosis and a
real PCP configuration acceptance case; this checkpoint makes no claim that the
option is broken or qualified.
