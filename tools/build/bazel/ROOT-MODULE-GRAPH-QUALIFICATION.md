# Normal AMD64 root module graph (2026-11-06)

## Native source-owned graph

sys/modules/BUILD.bazel now owns normal AMD64 root traversal as explicit typed leaf
products and parent module sets. Thirty-five source-policy groups preserve the
unconditional and architecture-specific roots and configured source/kernel choices.
The empty AMD64 flash parent is represented as an empty set, matching its Makefile;
it is not fabricated as a flash.ko product. Base installation consumes the same
configured runtime/debug Files as standalone products, without transitions, payload
copies or rewritten captured metadata. No Make query or frozen 722/729 inventory
runs in production actions. The source-owned declarations must evolve with source.

This is a qualified normal GENERIC/world profile, not complete option or platform
coverage. FDT-enabled, MMCCAM-enabled and TESTS-enabled root branches still lack
remaining parent/producer declarations. Selecting those incomplete branches fails;
they are not supported profiles and must be completed, not silently excluded.
MODULES_OVERRIDE, MODULES_EXTRA, WITHOUT_MODULES and ALL_MODULES are also not yet
implemented by this root. Individual older optional/foreign producers have their
own recorded coverage gaps. These remain migration work, not only runtime tests.

## Shared source and kernel policy

Root selection checks kernel KDTRACE_HOOKS, IPSEC, SCTP_SUPPORT/SCTP, INET/INET6,
FIB_ALGO, MMCCAM, DEV_ACPI, MAC, DDB, VIMAGE, SMP and KCSAN alongside the existing
FDT/IPsec/TCP settings. Source-owned GENERIC auto defaults use the same declaration
as normal native configuration actions, which check all actual generated option
headers before publishing identity/inventory. A changed source default cannot
silently disagree with analysis-time selection. The maintained complete source
checkout supplies opencrypto; behavior with that directory removed is not qualified.

Module IPv4/IPv6 support combines the corresponding source protocol choice,
source support choice and actual kernel option, preserving kern.opts.mk's tied
header rule. TCP parent selection now consumes that effective module support too.
Module ZFS follows its kernel source option, rather than the more restrictive
userland ZFS library selector. Kernel module VERIEXEC defaults off; explicit
veriexec=yes selects its five MAC products. This preserves kern.opts.mk's default
and is separate from userland auto/BearSSL policy and GENERIC's built-in Veriexec.
The new sourceless_host input and actual KCSAN option govern proprietary host blobs.

DEV_ACPI is generated by a device statement. The native rule therefore emits
nodevice/device acpi for explicit overrides, never nooptions/options DEV_ACPI.
All three architecture configuration declarations carry this device mapping.
Auto still emits no device override. Explicit disabled and enabled parser actions
both pass actual option/header validation. This is native configuration support;
it does not establish complete custom-kernel catalog or instrumentation support.

## Actual fixes found by full builds

The complete graph found a newer AMD VMM source's undeclared vmcb.h prerequisite.
Its existing package-owned physical header context now declares that header.
Disabling ACPI exposed amdsmu.h's reliance on an indirect ACPI include for bus-space
functions. The header now includes machine/bus.h itself. No warning is disabled,
option forced back on, source removed, or runtime authorization path changed.
The complete ACPI-off comparison also found iwlwifi linking fw/acpi.o regardless
of the kernel setting. Its object dependency, CTF sort-path inventory and all 110
source groups' CONFIG_ACPI flags now select from the same checked DEV_ACPI setting.
LINUXKPI_WANT_LINUX_ACPI remains unconditionally defined, as required by Make.
These source/header fixes need no new frontend or signing/staging protocol.

## Retained failures and limits

The one-time source migration's first pass mishandled Make's spaced .endif syntax,
leading to duplicate ixl selection and incorrect USB conditions. Native r1 rejects
the duplicate. Corrected source-policy generation retains explicit groups and a
balanced-condition assertion; both source-enabled and disabled traversal then match
Make. Migration inputs/policies remain under bazel-root-module-migration-r1-20261106
and bazel-root-module-migration-r2-20261106.
The generator is not part of the production build. Native default r2 retains the
missing VMM header failure; r3 passes, and r4 includes the amdsmu header correction.
The first ACPI-off profile retains amdsmu's missing bus-space declaration errors.

The first complete review stops on its omission of BLOB_OBJS from the observer's
link expectation. Review r2 uses the complete vector and finds iwlwifi's genuine
extra ACPI object. A separate full 726-recipe audit confirms that sole link mismatch.
Final default r5, off r3 and ACPI-off r4 include the complete iwlwifi fix and final
13-case audit test. Review r3 validates all profiles without filtering differences.
The first action observer expected one action per group; rules_cc registers both
regular and PIC variants. The final observer checks both, and the supplemental
proof binds actual linked object paths without a target-name whitelist. A query-only
unit fixture initially omitted its own sys.mk, then exposed the need to request expanded
Make policy values. The final fixture owns its source rule directory and checks
ordered prebuilt inputs and resolved aliases. An initial device observer looked in
opt_global.h; the correct DEV_ACPI output is opt_acpi.h. The normal build guard
already validates the complete option-header set; it was not weakened or changed
for that observer mistake. Empty failed device-review r1 is retained.

Existing format-5 frontend APIs carry the new settings and root targets; frontend C
and signing/staging/publication helpers need no interface changes. Backend source
rules, parser device semantics, maintained audit/tests, manual and plan change
together. No kernel I/O, filesystem, NSS or authentication hook is added. This does
not establish performance parity: CPU/RAM/disk I/O/footprint gates remain open.
