# Fourteen-program native rescue subset (November 2, 2026)

This adds actual original RESCUE variants for hostname, ln/link, mkdir, realpath,
rmdir and sleep to the qualified eight-program subset. The selected relative
order remains the original Make order: cat, echo, ed, expr, getfacl, hostname,
ln, mkdir, pwd, realpath, rmdir, sleep, test, head. Original red, link and bracket
aliases are preserved. Complete 103-program rescue, independent full-library
parity, installation and pkgbase remain open.

## Production graph and original reference

Six fresh original nested *_make targets retain the actual inherited parent
CRUNCHENV/CRUNCHARGS/CRUNCH_BUILDOPTS. They produce six regular application C
objects and five original DTrace provider objects. RESCUE does not disable these
five providers: WITH_COVERAGE_DTRACE and the original header and object
transformations are preserved. Hostname is untraced.

The source owners declare ordinary cc_library groups with actual ordered Make
warnings, GNU17, pipe/fno-common, O2, strong SSP and compressed debug. Sleep uses
the existing explicit libcapsicum header provider. Existing source-owned provider
specifications and bsd_dtrace_cc_objects transform only each application's own
objects. The regular output group passes rewritten code then its provider into
the original ordered stub/ld-r/crunchide stage. Original .o descriptors correspond
to conventional native regular .nopic.o names; actual order, content and unique
identity are checked explicitly, not inferred from a sorted artifact manifest.

The bounded dispatcher explicitly requires dtrace=true through the existing
required_configuration contract. This selects the original traced variant and
rejects unsupported alternate configuration rather than silently changing it.
No new frontend C/backend/helper API or SDK/toolchain policy is introduced.
Existing build-bsd format-5 source/test/compact/artifact contracts carry the
cohort, and its manual describes the selected programs. Make stays production;
BIP is excluded. No host rescue files or system configuration are installed.

## Actual compiler and provider proof

The six actual original compiler commands are independently replayed in private
object directories before DTrace mutation, with the exact selected compiler and
original generated-header roots. Original transformed objects, providers,
sources, headers and metadata remain hash-identical. All six native regular
compiler outputs match every executable and allocated section and nondebug
relocation. Actual warning/define/code-generation vectors match original Make.

Each original/native .d inventory contains 314 consumed occurrences. Every native
consumed file appears with its exact digest in the actual execution inputs. All
logical original/native file pairs match, including the declared source-owned
Capsicum header versus its installed SDK copy. All five generated provider
headers are whole-file byte-identical to original Make.

Five transformed C objects retain exact allocated sections and nondebug
relocations. The unchanged maintained ET_REL DOF verifier checks both actual
provider/rewritten-object pairs: provider attributes, complete probe argument
schemas, ordinary/enabled offsets, actual ELF relocation kinds/addends, bounded
hidden global function definitions, function byte hashes and NOP/XOR patch sites
match. This proves actual symbol-relative sites, not equal unresolved zero fields.

Full ten-section DOF descriptor/payload comparisons account for all remaining
encoding differences. Only path-key names that exactly match hash_obj's FNV
algorithm on the actual native relative path and original resolved path are
accepted. String references are resolved explicitly. One mkdir decimal key
length changes eight-byte alignment, nonloadable comment/provenance offsets and
total size: exact string end, zero padding, rounded offset, adjacent extent and
final size are asserted independently. All other descriptors and payload bytes,
including comment/provenance content, match. The rejected raw-layout comparison
is retained. Neither artifacts nor production checkers are rewritten/relaxed.
This is metadata/site parity, not loader registration, live address or event
firing qualification.

## Real static program and runtime

The actual native final link contains fifteen mandatory objects (main followed by
fourteen hidden program objects), then native util, libc and compiler_rt archives

only after matching their actual action-input hashes. All six new relocatable
links preserve original catalog object/provider order. Sixteen previous raw/hidden
captures are hash-identical to the accepted eight-program results and are honestly
reported as reused results rather than fresh spawns.

A fresh original generated-Make control intentionally consumes identical accepted
native application/provider, archive and startup bytes. It regenerates main,
compiles all fourteen stubs, runs all original ld-r/crunchide stages and links the
program. Generated main C, main.o, fourteen stubs, fourteen hidden objects and the
COMPLETE static ELF are byte-identical to native. This is independent original
pipeline/link proof on identical inputs, not an independent complete world or
static-library rebuild. The ELF is amd64 ET_EXEC with no interpreter/dynamic
segment, nonexecutable stack and GNU_RELRO.

One fresh Bazel wrapper executes 31 actual unittest methods, including all prior

DOF initialization is disabled before each product process starts; no host

The profile captures additional cc_library/default provider targets for audit;
its actual 18 CppCompile actions include five unused PIC application variants
