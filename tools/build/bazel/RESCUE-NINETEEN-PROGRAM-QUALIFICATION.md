# Nineteen-program native rescue subset (November 2, 2026)

Five actual original file-operation RESCUE variants add chflags, chmod, cp, mv
and rm/unlink to the fourteen-program subset. Original relative order and all
aliases are retained. Six C objects, five header/provider producers and twelve
additional private-file methods are included. This remains a bounded integration,
not full 103-program rescue, independent full-library parity, installation or
pkgbase qualification.

## Source-owned production graph

Five existing source owners declare normal cc_library variants with their actual
nested Make flags and own object order. Cp preserves _ACL_PRIVATE and cp.o before
utils.o; chflags declares the existing explicit Capsicum header dependency.
RESCUE and WITH_COVERAGE_DTRACE remain enabled as in original Make. Existing
provider specifications and bsd_dtrace_cc_objects generate the five headers and
rewrite each own regular object plus its provider. Conventional .nopic.o names
are bound individually to original .o identities. The final original crunch
pipeline receives application code in original order, followed by its provider.

The existing traced-selection guard, format-5 build-bsd target/test inputs,
selected SDK receipt, compact logs and immutable artifacts carry the change.
No frontend C/backend/helper API, toolchain, signing, security or publication
policy changes are required. The manual documents the bounded additions.
Production Make remains default; BIP is excluded. No host installation occurs.

Mv retains the actual RESCUE definitions of _PATH_CP and _PATH_RM: /rescue/cp
and /rescue/rm. Source, original staged header and selected native SDK paths.h
are byte-identical. Cross-filesystem mv may execute those fixed installed rescue
helpers. No replacement paths, environment override or command shim is added.
The current runtime cases exercise successful same-filesystem rename only;
installed helper/cross-filesystem execution remains an explicit guest gate.

## Actual Make, compiler inputs and filename controls

Five original nested *_make targets produce six C objects, five original -h
headers and five -G provider transforms. Actual inherited parent variables,
source/provider .d inputs, tools, metadata and objects are bound. Six recorded
original compiler commands are independently replayed into private raw outputs
before DTrace transformation, preserving every ordinary reference object and
provider. All six executable section payloads match native raw compiler outputs.

All 398 original/native consumed occurrences pair by exact content, with each
native .d file independently checked against its executed action-input digests.
All five generated provider headers are whole-byte identical to original Make.
Ordered warning/code-generation vectors and source defines match the actual
original compiler commands.

Four raw objects also match all ordinary Make allocated sections/nondebug
relocations. Chflags.c and cp.c instead contain the expected ordinary Make
absolute assertion __FILE__ literals versus canonical native relative names,
with corresponding relocation-addend changes. Those untouched mismatches are
retained. Two separate original Make controls include the unchanged component
Makefile then append exactly -fmacro-prefix-map=/usr/src/=. The actual commands
retain -MD/-MF/-MT and every other original flag, with only private generated
header roots relocated. Three controlled raw objects (chflags, cp and utils)
match all native allocated sections and nondebug relocations. No native filename
map, /usr/src constant, generated-output rewrite or source workaround is used.

Controls copy raw compiler outputs before invoking original provider generation.
All six transformed native C objects match allocated sections and nondebug
relocations against the three untouched programs and the two explicit controls.
This does not imply independent DWARF byte equality.

## Complete provider metadata and actual sites

The unchanged maintained ET_REL DOF verifier checks five actual provider and
symbol-object pairs: provider attributes, schemas, arguments, ordinary/enabled
offsets, ELF relocation kind/addend, bounded hidden function definition, function
bytes and actual NOP/XOR patch sites match. Cp genuinely has two input objects,
but all four probes belong to copy_file in utils.o; the verifier uses that actual
defining object and proves its matching aliases rather than assuming cp.o
contains every function or comparing unresolved zeros.

All ten DOF sections' descriptors and content are accounted for. Only aliases
that independently match hash_obj's exact FNV derivation on actual native
relative paths and original resolved object paths may differ. String references,
lengths, zero padding, eight-byte alignment, following nonloadable comment/
provenance extents and total size are validated arithmetically. Every other
section field and payload matches. This is symbol-relative metadata/site parity,
not registration, live address or event firing qualification.

## Accepted program, actual actions and runtime

The native final link contains twenty mandatory objects: main then nineteen
hidden program objects, followed by native util/libc/compiler_rt archives and
five native startup objects. Actual response files and every consumed object/
archive/startup digest are bound to the executed link. All five new ld-r stages
preserve exact original application/provider order. Twenty-eight previous raw/
hidden captures match the accepted fourteen-program qualification and are
reported as reused results, not invented fresh executions.

A fresh original generated-Make control intentionally supplies those identical
accepted native application/provider, archive and startup bytes. Generated main
C, main.o, nineteen stubs, nineteen original ld-r/crunchide outputs and the
COMPLETE static ELF are byte-identical to native. This proves original pipeline
and link behavior on identical inputs, not an independent full-world or static
library rebuild. ELF checks confirm amd64 ET_EXEC, no interpreter/dynamic segment,
nonexecutable stack and GNU_RELRO.

The first native run compiled and linked successfully but correctly failed its
43-method wrapper: the new cp -n test mistakenly expected status 0 when skipping
an existing destination. Maintained copy_file explicitly returns 1 in that case.
The failed source, log, compact records, compiler/.d outputs, response files and
ELF remain preserved. Only that test expectation was corrected; production bytes
were not changed. The accepted rerun has 43 passing actual methods in one Bazel
wrapper, with fresh TestRunner records. Its complete ELF hash equals the initial
actual CppLink output. Successful compiler/provider/link action provenance comes
from the first run and is explicitly joined by output digests to the accepted
captures; the failed first qualification is not relabeled as passed.

New cases cover private nodump/clear and invalid flags, numeric/symbolic chmod,
cp data/mode preservation/recursive symlink/no-clobber, same-filesystem mv and
no-clobber, rm file/tree and unlink alias. Existing 31 cases remain. DOF
initialization is disabled before product startup. No installed-path mv fallback,
ACL/filesystem matrix, original standalone ATF/TAP suites, live probes or host
configuration changes are qualified. Existing ed private /tmp scratch behavior
remains explicitly documented in the earlier subset.

Guarded jobs16 used the existing 18 GiB start/16 GiB reserve without interruption.
No CPU, memory, I/O, sandbox or caching-performance claim follows from timings.
The selected SDK/frontend contracts are unchanged. Libutil's original archive/
provider ordering, final DSO and installed-test parity remain separate gates;
all remaining rescue applications/libraries/options/architectures, complete
installation/package ownership, world/bootstrap, hardware and publication are
still open.
