# Native kernel aggregation guard (2026-11-02)

The explicit native amd64 GENERIC catalog now binds the parser's ordered input
metadata to public native object groups. Independent configured query r1 checks
all 2,285 groups expose exactly the 2,462 selected default link-product names.
The native rule rejects missing, ambiguous, duplicate-order and surplus object
names at analysis, constructs an explicit ordered File list in a provider, and
provides a separate parser-validation marker for the final linker to consume.
Dictionary membership avoids quadratic basename lookup. There is no object
content scan or per-I/O runtime mechanism.

## Maintained metadata

`amd64_generic_kernel_inputs.bzl` is checked-in migrated build metadata, including
source/origin, object, flags, compiler recipe text, dependencies and no-object
entries. It is not generated by invoking Make during a native build. It was
imported from the qualified original parser inventories and independently
reconciled native producer bindings. Keeping the exact parser metadata means a
new selected source, same-basename replacement, custom recipe change or selected
no-object generator change rejects a stale catalog. Changes require reviewing
native producers and updating their metadata together. The guard does not prove
that each compiler action implements its catalog recipe; the independent
compiler/input/artifact qualification remains necessary.

ZSTDIO and NFS_ROOT conditionals use the existing typed Bazel settings. All four
selections preserve the original parser order. Startup locore and the six
backend-generated suffix products remain explicit. The catalog currently covers
amd64 GENERIC; it is not arbitrary KERNCONF or ARM64/RISC-V aggregate support.

## Verification

- `bazel-kernel-link-input-groups-query-r1-20261102`: actual public group/file
  analysis, with no missing or surplus selected object names.
- `bazel-kernel-aggregate-guard-native-r2-20261102`, `...-zstdio-off-20261102`,
  `...-nfs-root-off-20261102`, `...-both-off-20261102`: real maintained frontend
  validation actions with 2,455 / 2,431 / 2,454 / 2,430 selected parser objects.
  Backend prefix/suffix adds seven products in each case.
- `bazel-kernel-aggregate-guard-host-tests-20261102`: Bazel executes the maintained
  five-method Python regression suite. It rejects addition/removal/order,
  source/origin/name/flags/recipe/dependency, no-object metadata, identity, schema
  and version drift. The frontend reports this plain test as one passed test
  case; this is not five separate Bazel/JUnit cases.
- `bazel-kernel-aggregate-guard-review-r1-20261102`: hash-verified captured marker
  receipts for all selections and the source commit manifest.

All evidence roots above are under `/usr/obj/usr/src`. These validation targets
need only configuration/tool outputs and metadata, not compiled kernel object
contents. The final linker must depend on the validation marker as well as the
ordered object Files. Its implementation and full kernel compilation/link/
post-processing/install qualification are the next gate, not completed here.

The initial combined artifact-and-host-test profile was rejected because kernel
profiles intentionally require a target harness for runnable tests. The corrected
kernel artifact profiles and separate userland host-test profile pass, retaining
the original failure. No gate was disabled. Controlled performance, full world,
modules, other architectures/configurations, packages, bootstrap and VM/runtime
qualification remain open. Make remains production/default; BIP stays excluded.

## Frontend integration

Existing format-5 `build-bsd bazel-test` inputs, jobs and typed feature settings
select these targets. This cohort adds maintained backend rules, helper and
Bazel tests; no new frontend C/manual option is needed. There is no alternate
build workflow or Make discovery in a production native action.
