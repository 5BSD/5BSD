# Native NTP library and ntptime candidates

2026-11-01. Make remains the production backend. This tranche declares the
105 maintained libntp translation units plus the generated version source,
ordinary and PIE private libraries, and ntptime. The other six NTP programs,
three private libraries and shared documentation remain migration work.
There is no whole-world, full NTP service, clock-control or publication claim.

## Source and generation ownership

The production graph uses source-owned rules_cc declarations and a reviewed
literal source list. It does not interpret Make metadata or import generated
BUILD files. Existing ISC public and private headers, textual interface-iterator
sources, libedit compatibility headers, threading, math and optional OpenSSL
edges have explicit owners. The only reused library edits widen two existing
header targets to the NTP subtree. No C source, installed-header copy, host
library fallback or source omission is introduced.

The maintained scripts/mkver remains the version generator. Its only external
commands are declared native cat, expr and rm; the shell, Python execution
runtime and libraries are explicit SDK inputs. It has no clock, hostname or
uname invocation. A single action owns a private .version seed, its increment,
version.c and provenance metadata. No input or source checkout is mutated.
Typed //usr.sbin/ntp:version_serial defaults to 1, matching fresh Make objects;
//usr.sbin/ntp:version_cset defaults to the empty revision. Serial 7 with revision
source.rev7 was independently generated by Make and matches native version.c
and .version exactly, as does the default version. Invalid counters and unsafe
version tokens are rejected. The upstream version literal is unchanged.

Make builds both ordinary objects and -fpie -DPIC objects for this internal
library. Native ntp and ntp_pie groups retain that distinction. ntptime consumes
the PIE group; it does not gain whole-archive linkage or extra dynamic library
dependencies. The internal archives are not installed.

Evidence is retained under /usr/obj/usr/src:

- bazel-ntp-libntp-make-r1-20261101 and
  bazel-ntp-libntp-noopenssl-make-r1-20261101: isolated maintained Make references
  with both private archive variants and 16 compilation jobs.
- bazel-ntptime-fresh-library-make-r1-20261101 and its noopenssl counterpart:
  recorded maintained Make program references, fresh objects and NO_ROOT stage.
  Explicit LIBNTPDIR selects the fresh libntp_pie.a for both DPADD and LDADD;
  actual diagnostic linker --trace output proves member selection and rejects
  the old staged private archive. Original expanded LDFLAGS are retained.
- bazel-ntp-final-default-qualification-r8-20261101 and
  bazel-ntp-noopenssl-qualification-r1-20261101: maintained build-bsd bazel-test
  with seven explicit native targets and two passing tests per configuration.
- bazel-ntp-version-serial7-qualification-r1-20261101 and its separate Make
  reference: explicit counter/revision generation, with exact output bytes.
- bazel-ntp-parity-r7-20261101 and bazel-ntp-noopenssl-parity-r1-20261101:
  both 106-member archives preserve Make member order and every member's
  defined/undefined symbol contract. Program ELF identity, PIE/interpreter,
  hardening, NEEDED order, dynamic symbols and versions match Make.
- bazel-ntp-default-install-parity-r8-20261101 and
  bazel-ntp-noopenssl-install-parity-r1-20261101: all four package installation
  records match paths/types/owners/groups/modes/tags; both native and Make
  installed binaries' real separate-debug CRCs validate. Package remains ntp,
  program remains /usr/sbin/ntptime; this component has no manual in Make.

The final default archives, program and generated source/counter are byte equal
to the reviewed r7 payloads. The default program's own object has identical
nondebug sections, including .text, to Make; only four debug provenance sections
differ. Complete archives and linked executables differ in bytes and final
section layout. Archive symbols and ELF metadata do not establish complete
machine-code or behavioral equivalence; no binary rewriting hides differences.
Actual execution records audit all 106 ordinary and 106 PIE source actions.
The OpenSSL-disabled audit separately checks 213 successful compile actions
(106 per archive plus the program), all without the three OpenSSL defines.
An unchanged final-default r9 repeat passes the same seven targets/two tests,
retains the exact 11-file artifact manifest and spawns zero execution records.
This establishes bounded cache reuse, not a controlled performance comparison.

The help-only test executes ntptime -h and checks its original exit status and
usage output. Source control flow exits before ntp_gettime/ntp_adjtime. It does
not qualify clock queries/changes or contact/configure an NTP service. The
version test checks input validation and refusal to overwrite existing output.
There are no maintained component test subdirectories in libntp or ntptime.

## Retained failures and remaining gates

Initial attempts remain in distinct r1 through r6 directories: a missing explicit
script export, executable-source attribute typing, an undeclared ISC private
header, an empty strict glob, non-PIE private library selection, and unsupported
BUILD kwargs syntax. The r5 link failure was fixed by declaring Make's actual
PIE object variant, not by disabling PIE or suppressing linker diagnostics.
Installation review also found and added the debug parent directory record.

The maintained frontend already accepts the local typed build settings and
explicit target lists through format 5. No new C frontend/backend option or SDK
restage is required. The manual records these same inputs. Default Make world,
kernel and pkgbase publication are unchanged. Cross-userland NTP, the remaining
NTP programs/libraries/docs, full package aggregation, isolated clock-control
runtime and controlled performance comparisons remain open.

Neither selected source group declares component DTrace providers or BSM audit
hooks. The migration preserves the original source and syscall behavior. A
separate policy review should assess observation/auditing of privileged clock
adjustment; absence of a component provider is not proof of missing syscall
coverage. No new instrumentation or tracing-performance claim is introduced.
