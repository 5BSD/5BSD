# Native BIOS interpreter family (2026-11-04)

## Implementation

Lua, Forth and simple BIOS loaders now share one maintained construction model
in stand/i386/loader/variants.bzl. Source-owned entry.bzl holds each original
36-context inventory, compiler operands, header views and explicit 37-object
link order. The Lua public labels and producer names are retained. The two new
public packages use the same i386 artifact boundaries as Lua, keeping firmware
artifacts separate from hosted CcInfo/tools.

All retain original text-only BIOS, GELI/disk/network/MD/ZFS support, static entry
at zero, no hosted startup/runtime libraries, actual guarded strip and native
BTX a.out packing. The shared version producer uses the same original version,
description and machine inputs with the existing explicit reproducibility policy.
Forth links regular i386 Ficl before BIOS/libsa32 archives; simple links no
interpreter archive. Other source profiles, including regular verifier-enabled
and graphical BIOS, remain incompatible pending qualification.

Default ownership is now declared input policy rather than a Lua constant.
loader_default_interpreter accepts auto/lua/4th/simp. Auto follows stand/defs.mk:
Lua if enabled, otherwise Forth if enabled, otherwise simple. Only the selected
interpreter installs /boot/loader and /boot/zfsloader hardlinks. All install
their own image. Only simple owns loader.help.bios, generated by the original
merge_help.awk over its original help.common input. Forth/Lua do not duplicate
that help file. All use source account/mtree archive policy and the declared epoch.

loader_pxe_interpreter now accepts auto/lua/4th/simp. Auto follows the selected
default; an explicit value independently chooses the corresponding real native
client. There is no replacement-client fallback. The previously unsupported
Forth/simple paths now build their actual qualified producers. Existing client
bounds, a.out packing, prefix ordering, block alignment and console options apply.

The six-method BIOS host test is shared by all three interpreters. It checks
actual ELF32/static-entry/BTX/client bytes, absence of the invalid inherited startup
debug link, exact installation membership, only the appropriate hardlinks, simple
help bytes, real tar modes/inodes and the actual strip boundary/failure behavior.
Policy inspection supplies the resolved default; tests no longer assume Lua owns
aliases in every configuration. Original Make stage/inode comparisons supply
independent checks of that policy, rather than relying on test/producer agreement.

## Frontend and limits

The maintained build-bsd.c/format-5 backend already accepts the declared flags,
public targets, installation providers and host artifact tests. No alternate
production entry point, C dispatcher or publication exception is introduced;
the manual and completion plan are updated. Source C/assembly, assertions and
preboot diagnostics remain intact. These components have no OS DTrace/BSM
provider to migrate; live observability is not established by artifact checks.

Actual interpreter execution, firmware/device/PXE/network behavior, graphical and
regular-verifier profiles, remaining IA32 variants, full world/kernel/pkgbase/
hardware publication, bootstrap, source/debugger parity and broad sandbox/cache/
incremental/CPU/memory/disk I/O/storage gates remain open. Client timing/RSS logs
are not complete persistent-JVM/system-build resource measurements.
Make stays production/default. BIP stays excluded. No host install, upgrade,
reboot, package publication or VM execution occurred in this batch.
