# ARM64/RISC-V input module qualification

## Current status (2026-11-03)

The normal build-bsd frontend passes four native Bazel kernel profiles: ARM64
and RISC-V, each with plain and CTF/split-debug settings. The selected cohort
contains 26 modules per architecture: evdev, uinput, usbhid and 23 HID leaves.
Thirty actual module C compilation contexts per profile include the generated
hid_if.c; evdev's cdev group owns two sources. Actual action logs, depfiles,
link parameter files and consumed generated inputs are retained before changing
profiles. All four captures contain zero failed actions.

All 104 original Make module variants pass. The 52 plain modules match
whole-file bytes. The 52 CTF/runtime comparisons preserve every ELF section and
section-layout contract except the separately validated GNU SHA1 build-ID and
debuglink values. Both original and native debuglink CRCs are valid. Standalone
debug files differ in 52 comparisons; semantic DWARF/source lookup remains
open.

All 120 actual module compilation contexts match original compiler policy and
13,522 canonical consumed input pairs. The 208 actual ordered link stages
preserve original flags and object order. All 156 original installation records
match destination, ownership, mode and package/debug tags. Original staged
payloads equal their Make products; each native installation source binds its
captured producer output. Before/after checks preserve 8,513 original
source/header/schema/tool bindings.

All four maintained frontend provider-test profiles pass: each checks four
required callback references and detects all four localized-provider negative
findings. These tests inspect actual cross-target artifacts on the native host;
they do not execute target modules. The initial declaration was rejected
because BUILD files cannot define reusable functions; the corrected reusable
macro lives in cross_input_tests.bzl. The failed attempt remains retained.

## Source-owned integration

Each module retains its existing source-owned object order, export policy,
installation package and aliases. Target-specific module declarations use the
registered ARM64/RISC-V kernel toolchains and existing link/CTF/debug/install
rules. The hgame provider keeps its three explicit public controller callbacks;
there is no kernel lookup-policy change.

hid, kbd and hkbd option headers are extracted from each target's actual
GENERIC configuration output, alongside existing evdev and usb options. Explicit
header views expose the required CK architecture inputs. KOBJ interfaces remain
native makeobjops.awk products of the declared schema, and USB identifiers remain
a native declared producer. No generated Make header or object is substituted
for a native Bazel action.

Generated KOBJ headers can differ from Make by a schema provenance comment:
Make records an absolute source path; the native producer records its basename.
The review must retain raw digests and permit only an exactly checked single
comment-line difference. Generated code and all other content must match.
Separate debug payload equality and debugger source lookup remain open.

## Observability and producer provenance

The bounded scan covers 29 unchanged physical C sources and finds 7
SDT/DTrace/CTR/audit marker lines. Exact final ELF comparisons preserve the
observed compiled probe descriptors, tracepoint data and relocations in 8
instrumented module variants. Live registration, input injection and
probe/audit event delivery remain unqualified. No probe source was removed.

KOBJ/USB producers were already cached during these profiles; no fresh
execution is claimed. Actual compiler inputs retain their generated bytes and
action-input digests before later profile changes. Original comparison checks
account explicitly for the single KOBJ schema provenance comment difference.
Option headers are extracted from each target's actual configuration tree.
Three trailing blank lines were subsequently removed from BUILD files with
identical parsed syntax; bindings retain the original profile source hashes and
final source hashes.

## Frontend and remaining gates

Existing build-bsd/backend format-5 architecture, kernel, CTF/debug and host
artifact test inputs carry this cohort. No frontend C, signing, staging-security
or publication policy change is required. All builds use /usr/obj and sixteen
jobs, without installation or execution of target modules on the host.
Completed receipts bind their original prepared SDK/tool state. Later changes
to receipt-bound tooling require fresh SDK snapshots; old receipt hashes must
not be rewritten to reuse an incompatible snapshot.

Full cross kernels/modules, alternate KERNCONF and input/USB/FDT options,
world/rescue/pkgbase, bootstrap, hardware/combined publication, runtime/VM and
controlled CPU/memory/disk I/O/disk allocation/cache/sandbox qualification remain
required. Input-device ownership, read/write/ioctl/mmap/revoke/grab, injection,
hotplug and detach/lifetime behavior require runtime tests. Compiled
instrumentation preservation does not prove live probe/audit delivery. Make
remains production/default; BIP remains excluded.
