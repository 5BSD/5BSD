# ARM64 / RISC-V64 GEOM and portable service modules

2026-11-01. Explicit native declarations cover 22 additional module candidates:
fifteen GEOM modules (ELI, flashmap, gate, label, Linux LVM, mirror, multipath,
nop, raid, uzip, zoned and BSD/EBR/GPT/MBR partition schemes), alq, nmdm, rc4
and the data/DNS/HTTP/TLS accept filters. All are selected by both architecture-
checked GENERIC Make inventories. This qualifies build/install artifacts for
these candidates, not full kernel/module sets, storage behavior or performance.
Make remains the production backend; BIP is excluded.

## Native graph and source policy

The declarations compile 57 original C sources and two RAID interface translation
units generated by the maintained makeobjops rule. Registered target C++
toolchains and declared headers feed the existing relocatable/CTF/export/shared-
link/separate-debug/install pipeline. No C routine, Makefile, runtime I/O path,
probe/audit site, production Make parser or output rewriting is introduced.
Existing amd64 source selections and dependencies remain unchanged.

GEOM, MAC and ZSTDIO option contents come from each target's actual generated
GENERIC config tree. GEOM label deliberately reuses the existing module-local
GEOM_LABEL header rule: its maintained Makefile explicitly generates that same
single definition, rather than inheriting every parent GEOM option. This is
module build policy, not a qualification-only replacement header. RAID interface
sources and export-all for flashmap, ALQ and RC4 preserve their existing policy.
UZIP's zlib/LZMA/worker sources remain unconditional; its ZSTD source is selected
with the existing typed kernel_zstdio setting and native Bazel select.

## Independent Make comparisons

All 88 default Make build/install combinations pass: 22 modules, two targets and
CTF/debug disabled or enabled. Commands, actual parent-kernel ARCH_FLAGS, objects,
generated inputs, resource counters and METALOGs are retained under
`/usr/obj/usr/src/bazel-cross-storage-make-20261101/`. Builds use all sixteen
logical CPUs. Normal NO_ROOT and -U/-M/-D flags stage without host installation;
NO_XREF excludes linker.hints. No module is loaded and no disk/provider is opened.

Four maintained `build-bsd bazel-test --arch arm64|riscv64` kernel-profile runs
each build 44 explicit module/install targets using existing typed CTF/debug
settings. Receipts:
`/usr/obj/usr/src/bazel-cross-storage-{arm64,riscv}-{plain,ctf}-r1-20261101/`.
No frontend API, signing or publication changes are required for these targets;
the manual records their expanded coverage.

All 44 no-debug module files match Make byte for byte. All 44 installed CTF/debug
modules match every ELF section and file offset except build-ID/debuglink
contents, including code/data, symbols, relocations, CTF and SDT where present.
Both native and Make debuglink CRCs validate against actual separate debug files.
Separate debug files retain DWARF/build-ID/symbol/layout differences; debugger
source resolution and full debug-file identity remain unqualified. All 132
file/debug install records match destination, type, ownership, mode and tags.
Directory metadata and linker.hints are outside this file comparison.

## Actual ZSTD-disabled branch

The independent maintained config tool generated two additional GENERIC parent
trees using an explicit include-GENERIC/nooptions-ZSTDIO input. The real resulting
opt_zstdio.h files are empty; no replacement header is written. Config commands,
wrappers and outputs are at
`/usr/obj/usr/src/bazel-cross-storage-zstd-off-config-20261101/`.

Four additional Make UZIP build/install combinations and four native frontend
runs pass with kernel_zstdio=false, for both architectures and CTF/debug modes.
The two no-debug binaries match Make exactly; enabled-debug installed sections
match under the same documented build-ID/debuglink limits, both real debug CRCs
validate, and all six file/debug install records match. References, receipts and
reviews use the prefix `/usr/obj/usr/src/bazel-cross-storage-zstd-off-` with
`make-20261101`, `{arm64,riscv}-{plain,ctf}-r1-20261101`, and `review-20261101`.
Direct symbol checks on all eight native and eight Make UZIP binaries confirm
ZSTD constructor/symbol presence in the enabled branch and absence when disabled.
The native branch matches Make, including the conditional object's removal.

Default review, source/input hashes, source scan, input JSON and reproduction
scripts are at `/usr/obj/usr/src/bazel-cross-storage-review-20261101/`;
`zstd-selection.json` records both branches. Kernel-profile runs intentionally
execute no target tests. Captured counters are not controlled CPU, aggregate RAM,
disk-I/O or allocated-disk performance measurements.

## Remaining gates

The bounded original-C scan records six SDT schemas in g_multipath.c. Other
scanned sources have no direct provider/schema/audit marker; generated/header,
GEOM/core/network observation remain separate questions. No probe is removed.
Live tracing/audit semantics and overhead remain unqualified.

Matching-kernel load/unload, provider lifecycle, partition/label probing, encrypted
I/O and key operations, mirror/multipath/RAID failure/recovery, compressed reads,
ZSTD-disabled errors, ALQ queues, null-modem traffic and accept-filter behavior
remain open. Compatibility RC4 artifact preservation is not cryptographic
validation. Full kernel/world/pkgbase production, debugger, cache/input mutation
and controlled CPU/memory/disk-I/O/disk-usage comparisons remain required.
