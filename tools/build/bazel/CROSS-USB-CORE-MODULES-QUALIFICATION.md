# ARM64/RISC-V USB core and peripheral module qualification

## Qualified scope (2026-11-03)

Twenty-two USB core/controller/storage/peripheral modules on each of
ARM64/RISC-V pass four normal build-bsd profiles/provider tests and 88 original
Make controls. All 44 plain modules match whole-file bytes; 44
CTF/runtime/debuglink comparisons, 240 actual compilers/30,264 canonical
consumed input pairs, 176 ordered links and 132 original installation
records/payload bindings pass. Target FDT adds usb_fdt_support.c; a real cp2112
Make prerequisite omission is corrected in both build descriptions. Separate
DWARF/source lookup and device/runtime/performance gates remain open. See
[CROSS-USB-CORE-MODULES-QUALIFICATION.md](CROSS-USB-CORE-MODULES-QUALIFICATION.md).

All 44 plain modules equal original Make whole-file bytes. All 44 CTF/runtime
comparisons preserve every ELF section and layout contract except explicit
build-ID/debuglink values. Those descriptors retain their metadata/encoding,
and native and original separate-debug CRCs pass. All 44 standalone debug
files differ; semantic DWARF and actual debugger source lookup remain open.

The 240 actual module compilations preserve compiler policy and 30,264
canonical consumed source/generated-input pairs. All 176 actual link stages
preserve flags and object order. The 132 original install records match native
destinations, ownership, modes and package/debug tags. Original staged bytes
bind Make products; native install sources bind captured producer outputs.

Before/after checks preserve 8,600 source/header/schema/tool/Make-policy inputs.
The 44 source-list queries retain actual parent-exported values, GENERIC
KERN_OPTS and 57 regular Makefiles. /dev/null is recorded separately as an
explicit empty configuration sentinel. Original controls compile one module
at a time with all sixteen logical CPUs and private NO_ROOT stage/METALOG
outputs. No host installation or target module execution occurs.

## Source-owned integration and actual Make correction

The cohort contains 48 source groups, 59 physical C sources and the native
KOBJ-generated usb_if.c. Native Bazel source/object order, exports, package
and aliases are explicit source-owned declarations. Make queries are migration
reference evidence; normal Bazel builds neither query Make for discovery nor
import Make-produced objects or headers.

Both target configurations enable FDT. Their actual USB object list appends
usb_fdt_support.o, unlike the existing amd64 module. Its native producer
includes the independent Make unit's physical header closure and generated
OFW/bus/device interfaces. Existing precise header providers are reused with
consumer visibility extensions; the additional USB-local header set is
explicit. Options are extracted from the selected target configuration tree;
no option contents or empty substitutes are invented. Existing cross-target
CK headers are reused for the controller package.

The first original run passed 84 controls and failed four cp2112 builds.
With FDT enabled, gpiobusvar.h includes ofw_bus_subr.h, which requires the
generated ofw_bus_if.h. The module Makefile omitted that prerequisite. Its
SRCS now declares ofw_bus_if.h when OPT_FDT is nonempty, and the corresponding
cross-target Bazel producer declares the OFW interfaces and physical closure.
The fresh complete r2 control run passes all 88 builds. Failed logs remain
retained; no failed run is counted as qualification.

KOBJ comparisons retain raw hashes and check the complete generated bytes.
Only one exact schema-provenance comment line may differ, recording absolute
source path versus basename. The explicit schema table covers the interfaces
actually consumed here; no arbitrary comment or code normalization occurs.

Four native-host provider tests inspect all selected target modules. They
require ehci and xhci to resolve usb_bus_mem_alloc_all through usb, umass to
resolve usb_get_serial, and cp2112 to resolve usbd_req_get_report. The checker
rejects localized known providers. External kernel providers and actual module
loading remain outside this artifact check's scope.

## Observability and remaining qualification

The bounded 59-source scan finds 26 explicit instrumentation marker lines in
cp2112.c, usb_dev.c, usb_hub.c and usb_transfer.c. Twelve module variants
contain matching compiled SDT/tracepoint sections, whose contents and layout
match Make. The other sources have no matching explicit markers in this scan;
that does not establish missing framework/FBT coverage. Keep runtime checks
for USB controller enumeration, interrupts/DMA, transfer cancellation, GPIO/I2C,
mass-storage attach/I/O/eject, gadget/template selection, video/framebuffer
operations, hotplug, suspend/resume and detach/lifetime handling. Live probe
and audit delivery are unqualified; no instrumentation source was changed.

All four profiles use the existing maintained build-bsd bazel-test format-5
kernel target/architecture/CTF/debug/test inputs and native-r3 execution SDK.
Existing backend rules carry the new targets without frontend C/CLI, signing
or publication-policy changes. Manual and roadmap coverage are updated in the
same commit. Receipt-bound tool changes require a new validated snapshot;
completed receipts are not rewritten.

The current independent configuration audit remains referenced, not a claim
of compiled cross kernels. Full cross kernels/modules/options, world/rescue,
aggregate installation/pkgbase/hardware/verified combined publication, latest
Bazel packaging/bootstrap, semantic DWARF/source lookup, VM/runtime and
controlled CPU/memory/disk-I/O/disk-allocation/cache/sandbox comparisons remain
required. Retained time/resource counters and disk guards do not constitute
performance qualification. Make remains production/default; BIP is excluded.
No host installation, upgrade, module load or reboot is performed.
